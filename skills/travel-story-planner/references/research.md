# 攻略资料与景点候选

## 来源分工

| 来源 | 用途 |
| --- | --- |
| [小红书](https://www.xiaohongshu.com/)、[知乎](https://www.zhihu.com/) | 优先发现景点，研究亲历体验、停留时间、人员适配、交通衔接与避坑信息 |
| [携程攻略/游记/点评](https://you.ctrip.com/)、其他可读取的旅行社区 | 补充候选与实际体验，交叉参考不同人群和季节 |
| [TripAdvisor](https://www.tripadvisor.com/)等海外旅行社区 | 海外补充来源；无中文结果时尝试英文、当地名称 |
| 景点官网、官方预约平台、最新公告 | 核验开放/闭馆、最后入场、预约、临时关闭、游客服务和设施运营等事实 |
| 当地文旅/旅游局官网 | 补充地区介绍、景点身份、官方交通/服务入口 |

以社交攻略为体验研究的起点，不要求读遍每个平台。来源的适用性取决于是否亲历、背景是否相近、日期是否适用与资料能否核验，不只看点赞或搜索排序。

## 检索方法

把目的地与具体用户背景组合检索，而非只搜“必去景点”。按需要换词，例如：

- `杭州 三天 老人 少走路 攻略`
- `杭州 亲子 雨天 游记`
- `西湖 实际步行 游览多久 休息`
- `site:xiaohongshu.com 目的地 亲子 攻略`
- `site:zhihu.com 目的地 哪些景点值得去`

站内搜索或通用搜索均可。没有结果、正文不可读、页面太大或需要登录时，先尝试其他可访问正文和备用平台；仍不足则说明缺口，必要时请用户分享愿意提供的攻略。搜索摘要只能当发现线索，不能当读过全文的证据，不捏造作者观点、点评或亲历数据。不绕过访问限制。

## 读取与比较

提取“谁去的、何时去的、去了哪些景点、停留多久、交通怎么衔接、哪里累/值得、当时有哪些限制”。优先匹配季节、人群和节奏，再考虑新旧。

多篇独立亲历记录能帮助判断共同体验；转载、营销复用不算独立证据。区分推广与体验，不把单条差评或高热度直接转为景点好坏结论；“不适合本次”应有与用户需求相关的理由。

涉及开放、预约、设施、关闭等会决定可行性的信息，入选行程前回官方核验。未知余票不能说成可订。官方与攻略冲突时，运营事实依最新适用公告，体验差异保留为不确定性。

## 景点卡片的粒度

每个有希望入选的景点记录：

- 正式名称/别名、所在区域，避免同名异地、父景区/子景点重复计数。
- 一两句特色与看点，以及为什么适合/不适合当前用户。
- 建议停留时间范围及对应游览范围（门口/周边、短线、主要景点、整日或多日），保留相近人群的参考依据；资料不足时标注估算与缺口，不能为了塞进当天随意缩短。景区代表点、入口和内部景点区分清楚，地图位置核验不能替代游览时长研究。
- 步行或爬山负担、是否需休息、与同行人员相关的设施或限制。有索道不等于全程不费脚力，但只需概括影响，不研究详细景区内部路线。
- 开放、预约、天气影响等必要注意事项，以及核验缺口。
- 来源链接、资料日期（能取得时）和核验时间；攻略体验与官方事实分开标明。

不展开“景区内怎么玩”的细节，不为每个景点制作打卡路线或多套玩法。路线建议用于景点间的顺序与交通。无需给所有低相关候选补齐卡片，先筛选再深入。

保留用户必去项；如有闭馆、天气或体力冲突，解释并沟通，不静默移除。候选按“优先考虑、可选、不适合本次”表达，不声称找全全部景点，不编造量化评分或排名。
