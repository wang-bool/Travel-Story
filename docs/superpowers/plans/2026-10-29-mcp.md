# Travel Story MCP Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for isolated tasks and inline integration. Check off tasks after verification.

**Goal:** External Agents edit local trips through 13 MCP tools and control the existing browser UI.

**Architecture:** Server-owned JSON repository serializes transactions; pure domain operations enforce invariants. Browser and MCP bridge use one validated action API. SSE distributes data/view events; browser acknowledges commands.

**Tech Stack:** Next.js 15, TypeScript, React, Node stdio MCP, existing MapLibre/Turf providers.

## Implementation seams
- Service execute(action, input) returns JSON objects; DomainError carries code/message.
- Browser GET /api/trips reads snapshot; POST /api/travel executes actions; GET /api/events notifies snapshots changed. All writes go through service.
- MCP-only POST /api/mcp requires bearer token from data/mcp-token; stdio launcher reads token via explicit configured data directory.
- get_trip includes full business state excluding route geometry by default; web snapshot retains geometry.
- View registry owns commands and view leases independent of trip persistence.

## Checks
For each task: introduce behavioral test, observe failure, implement, rerun targeted tests. Integration checks must use temporary data directories. Static tests do not substitute for MCP transport tests. Document verified versus unavailable GUI checks honestly.
