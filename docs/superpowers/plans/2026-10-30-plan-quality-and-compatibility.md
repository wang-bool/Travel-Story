# 计划质量与 MCP 兼容性调整

用户已授权改进 Skill 的规划检查，并通过 MCP 帮助 Agent 正确执行。

## 设计

- Skill 第一阶段完成条件包含区域组合、住宿/预约导致的必要往返、大型景区游览范围、真实到离边界、每日时间账和体力检查。用户确认不替代可行性检查；发现冲突先说明并调整。
- 新建 apply_plan 任务需提交 review：区域安排说明及逐日可用、交通、游览、用餐休息、缓冲分钟数与依据。服务端只检查结构、日期覆盖和算术，不宣称核验了来源或真实停留时间；超时在创建任何行程前拒绝。旧任务保持原参数恢复。
- stdio 桥在状态结果中明确报告网页兼容性；首次写入复用状态或检查一次，拒绝旧网页服务。UNKNOWN_TOOL 转为明确版本错误，禁止自动回退低层写入或 HTTP/UI 重录。ensure_service 复用服务不等于升级服务。
- 保留16个工具，局部修改仍用低层工具；正常兼容连接不增加每次调用的健康检查。

## 执行顺序

1. 添加旧网页阻止写入、兼容状态恢复、无重复预检与丢失响应不重试的回归测试。
2. 添加缺 review、超时、日期缺项、合理计划和旧任务兼容的回归测试。
3. 实现桥接兼容状态及新任务时间账校验，更新工具说明和能力标志。
4. 更新 Skill、速查 JSON 示例、MCP 文档和浏览器 smoke 的输入；校验所有示例。
5. 运行全套测试、类型检查和隔离构建；用真实 SDK 验证协议。保留用户数据与运行进程，不自动修改 Trae 全局配置。
