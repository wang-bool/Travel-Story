# Travel Story 开源前清理设计

## 目标

本轮工作将 Travel Story 整理成适合个人下载和自行部署的开源项目。工作范围包括文件清理、密钥与隐私检查、输入校验、代码质量检查、现有界面问题排查，以及开源文档补全。

项目按单用户自部署工具处理。服务通常由使用者本人运行和访问，本轮不增加账号系统、API 鉴权或多租户隔离。

## 本地文件处理

删除 `测试截图/`。这些图片来自开发测试，不作为 README 素材使用。

以下内容保留在当前电脑中，并由 `.gitignore` 排除。

- `.env.local`
- `data/`
- `tile-cache/`
- `.next/`
- `node_modules/`
- `tsconfig.tsbuildinfo`

`data/` 中现有的行程、媒体和录像属于用户本地内容，不删除、不移动，也不复制成示例数据。项目继续使用 `lib/seed.ts` 生成演示行程。

补充 `.gitignore` 时覆盖日志、编辑器缓存、临时文件、环境变量变体、录制帧目录和常见构建产物。忽略规则修改后使用 `git check-ignore` 逐项核验。

源码文件只有同时满足以下条件时才会删除。

- 没有静态引用或框架约定入口用途
- TypeScript 未使用代码检查没有发现外部依赖
- 删除后类型检查和生产构建通过

## 密钥与隐私

`.env.local` 中存在已经设置的 `GAODE_KEY` 和 `LOCATIONIQ_KEY`。检查过程不得打印或复制密钥值。该文件保留在本机，并继续被 Git 忽略。

`.env.example` 只保留变量名、用途和安全占位说明。服务端密钥不得使用 `NEXT_PUBLIC_` 前缀，也不得出现在客户端源码、README、需求文档、测试数据或构建输出中。

发布前建议用户在服务商后台轮换当前密钥。轮换操作不属于本轮文件修改范围。

密钥扫描覆盖源码、配置、文档、脚本和待提交文件。`node_modules/`、`.next/`、本地数据、瓦片缓存与用户指定保留的 `.env.local` 不进入待提交扫描范围。

## API 输入保护

本轮不增加鉴权。API 保持单用户自部署用法，并增加防止误操作和损坏本地数据的校验。

- 媒体与录像上传检查请求声明大小和实际读取大小
- 上传上限通过服务端环境变量配置，并在 `.env.example` 与 README 中说明默认值
- 素材 ID、帧文件名、帧会话 ID、扩展名和 MIME 类型使用白名单
- 行程写入检查请求体大小和顶层数据结构
- 行程库与素材元数据使用临时文件和原子替换，降低中断时留下半文件的概率
- API 响应返回短错误码或用户可读说明，不返回服务器路径、异常堆栈或完整 `ffmpeg` 输出
- 地理编码与路线接口保留现有进程内限流，并在 README 中说明它不适用于面向陌生用户的公网服务

上传限制使用以下环境变量和默认值。

- `MAX_MEDIA_UPLOAD_MB` 默认 250 MB
- `MAX_RECORDING_UPLOAD_MB` 默认 512 MB
- `MAX_FRAME_BATCH_MB` 默认 64 MB
- `MAX_TRIPS_BODY_MB` 默认 10 MB

所有值允许自部署用户按机器内存和素材大小调整。接口超过限制时返回 HTTP 413。无法取得 `Content-Length` 时仍读取请求，并在读取后检查实际大小。

## 依赖处理边界

不修改依赖版本、`package.json` 或 `package-lock.json`。

当前 `npm audit` 报告包含三个高危项，涉及 Next.js 及其间接依赖 `postcss` 和 `sharp`。README 的安全说明和最终审计报告记录这个结果，不执行 Next.js 16 升级，也不使用 `overrides` 强行替换间接依赖。

## 代码与界面检查

使用 TypeScript 的未使用代码检查、引用搜索、类型检查和生产构建寻找陈旧代码。只做能由检查结果证明安全的小范围删除或整理。

检查重点包括地图初始化、地图监听器释放、动画播放控制、录制结束后的资源释放、重复计算和长期驻留的大对象。涉及模块边界调整、录制架构重写或存储层更换的建议只写入报告。

现有视觉方向保留。`app/globals.css` 暂不拆分。界面检查只处理能够稳定复现的文字裁切、内容溢出、响应式问题和基础可访问性问题。新的布局体系、视觉重做或大范围组件拆分需要另行确认。

## 需求文档更新

保留并更新 `需求文档.md`。更新以当前源码和可以运行的功能为依据，不把旧设想写成已经完成的能力。

文档按已经实现、部分实现和后续计划区分功能状态。已废弃的数据结构、页面流程和实现描述应删除或改成现状。尚未在源码中出现的云存储、多用户协作、自动内容理解等能力保留在后续计划中，并明确尚未实现。

## 验证

完成修改后执行以下检查。

- `npm run typecheck`
- `npm run build`
- TypeScript 未使用代码检查
- `npm audit --registry=https://registry.npmjs.org`
- 密钥模式扫描
- Git 待提交文件扫描
- `git check-ignore` 验证本地密钥、数据、缓存和构建产物
- README 中的本地图片路径检查
- 关键 API 的合法请求、超限请求和非法标识输入检查

生产构建、类型检查或关键 API 验证失败时，本轮不能标记完成。依赖审计仍报告已确认的高危项不算验证失败，因为用户已经明确要求保留当前依赖版本。最终交付须列出删除内容、修改内容、验证结果和仍需用户处理的事项。

## 不在本轮处理的内容

- API 鉴权与账号系统
- 多用户数据隔离
- Next.js 16 升级
- 依赖版本调整
- 存储层改为数据库或对象存储
- 地图与录制模块的大范围重构
- 全站视觉重做
- 用户本地数据、媒体、录像和瓦片缓存删除
