# 旅行 Skill：天气模块需求稿

状态：天气部分已落地到 [Skill 天气参考](../../../skills/travel-story-planner/references/weather.md)，该文件为当前执行版本；下文保留天气模块讨论记录。MCP 展示第二部分尚未实现。来源入口核验日期：2026-10-29。入口预先固定，预报与预警内容必须在每次规划时实时读取。

## 使用位置与前提

收集目的地、出行日期和同行情况后，先查询天气，再筛选景点和编排行程。多城市行程分别查询；山区、海岛等需核对具体游览区域，不能将市区天气直接等同于山顶或海上天气。

天气通过客户端现有联网工具查询；当前 Travel Story MCP 不提供天气工具。联网不可用时如实说明未能核验，不声称已经查询。

## 固定来源与回退

| 场景 | 固定入口 | 用法与限制 |
| --- | --- | --- |
| 中国大陆逐日天气 | [中国天气网](https://www.weather.com.cn/)；[上海城市页示例](https://www.weather.com.cn/weather/101020100.shtml) | 从城市导航找到实际目的地，不编造城市代码。城市页提供7天与8–15天入口；读取日期、天气现象、温度和风。示例城市不作为其他城市的默认位置。 |
| 中国大陆重要天气、预警与交叉核验 | [中央气象台预报入口](https://www.nmc.cn/publish/forecast.html)；[大风预警栏目](https://www.nmc.cn/publish/country/warning/wind.html)；[中国天气网预警频道](https://www.weather.com.cn/alarm/) | 在中央气象台导航中进入暴雨、大风等相应栏目，并核对目的地当地气象部门的预警信号。全国公报和地方预警信号范围不同，不能将全国预警当成每座城市都受影响。 |
| 海外逐日天气、国内预报的备用来源 | [Open-Meteo 官方文档与查询入口](https://open-meteo.com/en/docs) | 按核验后的目的地坐标与当地时区查询。默认7天，最长16天；具体以实际返回为准。可查温度、降水、风与阵风、紫外线等。该预报不能代替官方灾害预警。 |
| 海外官方预警定位 | [WMO 严重天气信息中心](https://severeweather.wmo.int/)；[预警来源列表](https://severeweather.wmo.int/sources.html) | 用于定位发布机构及预警，最终核对当地官方原文。页面空白、未覆盖或无法读取均不等于当地没有预警。 |

常用地区可直接进入已核验的官方预警入口：[日本气象厅](https://www.jma.go.jp/bosai/warning/)、[法国气象局](https://vigilance.meteofrance.fr/fr)、[美国国家气象局](https://www.weather.gov/)。日本等交互页面可能需要浏览器渲染；仅取得页面外壳不能算查询成功。

优先读取固定入口，不必每次重新比较天气网站。入口失效、无法提取实际数据、目的地区域未覆盖或来源冲突时，再查找当地官方替代来源并说明缺口。普通查询不必遍历全部来源；普通天气预报与官方预警须分别核验。

Open-Meteo 如后续被集成成应用内天气 API，需要另行检查其当时的商业使用与调用条款；本需求稿不新增该集成。

## 日期、数据与不确定性

- 使用目的地当地日期和时区，确认返回覆盖真实出行日期。记录查询时间，保留原始来源链接；预警还应记录发布机构、发布时间、等级、受影响区域、生效/失效时间，字段缺失如实说明。
- 先查询，再说明结果。覆盖不足时列明可查到哪一天、哪些旅行日期尚未覆盖；不能武断认定所有来源都只有未来7天。
- 因日期太远而超出范围：明确说明尚无覆盖该日期的逐日预报。季节气候可以单独作为背景，不得伪装成具体日期天气。
- 访问失败或数据缺失：说明未能取得资料，不能说成“时间还早”。
- 8–15/16天等较远期预报标为趋势性参考，临近出发需重新核验。只提醒用户届时复核，不声称会在后台自动追踪。
- 对同地点、同日期的重要分歧进行交叉核验并说明，不挑选更晴朗的一家当结论。
- 概率、累计降水、天气描述各自保留含义；降雨概率高不等于暴雨。模型天气代码的“强降雨”不直接冒充当地官方“暴雨”等级或预警。
- 日天气代码、日累计降雨可能反映一天中的最强天气，不能直接断言全天都下雨；影响安排时进一步核对时段资料。

## 行程决策规则

以下为用户指定的规划沟通规则，不是气象部门的预警标准。

1. 晴、阴、普通小雨且无相关官方预警：直接继续规划。说明影响，安排晴雨替换和携带物品，不反复询问“还去不去”。
2. 行程明显受持续恶劣天气影响，例如5天中有2–3天预报暴雨：先反馈具体日期、区域、来源及可能受影响的活动，再请用户选择照常出行并调整、改期或更换目的地。不要将这个例子硬编码成适用于所有长度旅行的比例阈值，也不要等待凑够2天才提示单日严重影响。
3. 发现与出发地、途经地区或目的地及出行时段相关的大风、暴雨等官方预警：主动反馈等级、时效和涉及区域，与用户确认如何调整；不能只对橙色/红色预警才沟通。过期、已解除、或仅覆盖不相关地区/日期的预警，不触发本次出行确认。
4. 预警通常覆盖较短时间：当前预警不自动说明数周后的旅行有同样预警。注明时效，临近出行再核验。未查到预警只能说明本次核验情况，不能保证整个旅行期间不会发布。
5. 提供继续规划所需的选择和初步替代思路，在收到用户决定前不定稿受影响的安排；不擅自取消、改票或预订。官方封闭、停运或禁止进入的项目不作为“用户同意就能照常进行”的选项。

## 用户反馈内容

先给总体判断，再按日期或天气相近的时段简述：天气、温度、降水、风/阵风及相关预警。说明对现有旅行偏好与同行人员的实际影响，然后给简短的穿衣、雨具、防晒和补水建议。

建议以实际资料为依据：温差大提醒分层穿衣，有雨提醒防雨；大风时考虑雨衣而非只建议打伞；缺少紫外线数值不编造指数。资料缺失与尚未覆盖的日期明确列出。

普通天气继续景点研究；持续暴雨或相关预警先提出明确的调整选择，等待用户决定。不要用一次成功预报查询代替预警核验。

## 后续验收场景

- 5天行程，2天下小雨、无相关预警：继续规划，提供雨具和室内备选，不要求确认去不去。
- 5天中3天预报暴雨：列明受影响日期和证据，请用户确认是否调整。
- 只有1天，但目的地与旅行时段有有效大风预警：同样触发沟通。
- 数周后出行，当前有即将结束的暴雨预警：不将当前预警套用未来日期，说明预报范围不足。
- 预警页面只有地图外壳、无具体数据：标记未核验，不能输出“无预警”。
- 旅行10天，来源覆盖前7天：标明后3天缺口，按固定备用来源尝试补充；不填造天气。
