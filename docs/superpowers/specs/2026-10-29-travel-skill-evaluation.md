# 旅行规划 Skill 行为验收

范围：第一部分，模拟资料/对话测试；不写入真实行程、不预订、不访问真实账号。联网来源沿用已核验入口，这里不将模拟天气当成实时预报。

## 可重复场景

### A：需求尚不完整

用户：从苏州去杭州玩三天，夫妻带一个7岁孩子，想悠闲点，帮我规划一下。

检查：承接已有出发地、目的地、天数、人数和节奏；先补日期等关键缺口，后续再补偏好/脚力/固定安排/日作息；不主动问预算、不一口气发全量问卷，不声称已查出行天气。

### B：预报范围与预警时效

用户：下个月中旬去海边5天，资料里今天有大风黄色预警，天气页只到未来第7天，先按这个排。

检查：当前预警不套给下月；逐日预报尚不覆盖要明示；只做待天气核验的初稿，不虚构未来天气；视缺口补目的地和具体日期。

### C：体力、闭馆与资料不足

苏州去上海，2成年人及1位70岁老人，连续步行约30分钟需要休息，公共交通，09:00出门/18:00返回。第1天12:00到站，第3天16:00火车离开。偏好城市文化，只要景点级建议、住宿和餐饮区域，不指定酒店餐厅，不录入应用。

模拟资料：第2天小雨，无相关有效预警；亲历攻略中博物馆停留2–3小时，第二篇为同文转载；官方说明该博物馆第2天闭馆；江边攻略为1–2小时且无台阶；交通耗时未知。

检查：小雨不要求确认是否取消；不把转载当独立证据；第2天不排已知闭馆景点；考虑首末日交通/行李/餐饮/休息和步行上限，不能机械增加停留时长而仍安排连续步行1–2小时；未查到交通耗时标估算/待核验，不宣称精确可执行；不新增景区内部详细游线、不问预算、不调用MCP写入。

### D：恶劣天气沟通

同一已知目的地5天行程，有可靠预报3天暴雨；另一个变体是仅1天相关有效大风预警。

检查：列明受影响日期和区域，询问调整/改期/换目的地或在允许条件下继续，不擅自定稿受影响安排。不能等到多日暴雨才理会单日预警，也不能只关心橙红预警。

### E：社交平台不可读取

搜索结果列出小红书和知乎相关文章，但正文均不可读取；只取得标题摘要。官网仅能核验开放与预约。

检查：承认攻略体验资料未核验，尝试可读取的游记/点评或向用户索取愿意分享的内容；不能声称读过文章、编造作者体验或评论。官网能支撑运营事实，不能替代用户指定的攻略体验研究。

## 判定方式

检查模型实际回复/操作选择是否满足以上行为；格式校验不代替行为测试。本文件记录复测结果及证据，不作为 Skill 运行时依赖。

## 无 Skill 基线观察

独立模拟 A 的开头是“可以，先按每天一个主要活动、午后留休息时间来安排”，随后先列三天框架，再问日期、到离和每日作息。它能意识到时间缺口，但没有按本项目要求先收集背景、再进入研究与排程。因此入口明确先补关键背景，不先生成完整日程。

基线 B 已正确区分当前预警与未来预报范围；基线 C 已正确处理闭馆、转载和步行休息，不把这些表现记录为失败。验收保留这些场景用于检查新 Skill 没有引入退步。本轮不对真实旅游方案质量作统计推断。

## 加载 Skill 后的独立复测

独立 Agent 只读取 SKILL.md 及3个相关参考文件，执行 A–E，未联网或操作应用：

- A：先承接“苏州出发、两大一小、杭州三天、悠闲”，仅补日期/大致月份；没有先排三天日程、重复询问已知背景或询问预算。该项相对基线流程改善。
- B：指出“今天的大风黄色预警不能直接代表下个月中旬”，补目的地和日期，先核对预报覆盖与预警时效；没有编造未来天气。
- C：输出有缺口说明的初稿，避开第2天闭馆，普通小雨继续规划；引用一份独立亲历资料，连续步行限制为30分钟并核验座椅；首末日保留行李、吃饭、休息与进站时间，不编造交通分钟数或景区内部游线。
- D：3天暴雨先沟通调整；单日相关有效黄色大风预警同样沟通，不等橙红预警，官方关闭项目排除。
- E：明确摘要不能当作已读亲历攻略，尝试可访问旅行社区或用户愿意分享的正文；官网仅支撑运营事实，不输出假装核验过的适配结论。

本轮5个模拟场景满足验收条件。它们检验流程行为，不代表所有真实平台都可访问，也不保证真实旅行预测准确。
